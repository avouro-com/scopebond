Managed tool settings. A workspace rules document may carry a `tool_settings` section, signed on its own with the workspace key and checked with the rules check itself (`checkToolSettingsSignature`; its signed payload adds `kind: "tool_settings"`, which a rules payload never carries, so a rules signature never passes for it, nor the reverse): for each AI coding tool, permission rules to allow and to deny and MCP servers it may or may not start, and `mode: "enforce" | "report"`. The hook carries it (a changed section at the same rules version is installed; an answer without one leaves the installed section), and sends the agent's version (`x-scopebond-agent-version`) and report (`x-scopebond-tool-settings`) on the agent's rules check. The Scopebond Agent applies a section only when a trusted key signed it (otherwise `refused: unsigned`, nothing written): to Claude Code's `~/.claude/settings.json` (`permissions.allow`/`deny`, `allowedMcpServers`/`deniedMcpServers`) and the Cursor CLI's `~/.cursor/cli-config.json` (`permissions.allow`/`deny`, denied servers as `Mcp(<name>:*)`); Codex (per-server settings in TOML, which Scopebond does not rewrite yet) and GitHub Copilot are reported as unsupported. Only entries Scopebond added are ever removed, a list it created goes once empty, other keys and entries stay, the file is backed up once and replaced atomically, a file that does not parse or is a symbolic link is never written, `CLAUDE_CONFIG_DIR` is honoured, rules without a section report `not_delivered`, replay marks are kept per workspace, entries with bidirectional or invisible formatting characters are refused, and each tool is reported as applied, drifted (setting names only, never values) or refused; a drift is put back only in enforce mode.
