Managed tool settings. A workspace rules document may carry a `tool_settings` section, signed on its own with the workspace key and checked with the rules check itself (`checkToolSettingsSignature`; its digest covers its own `type`, so a rules signature never passes for it, nor the reverse): for each AI coding tool, permission rules to allow and to deny and MCP servers it may or may not start, and `mode: "enforce" | "report"`. The hook carries it (a changed section at the same rules version is installed; an answer without one leaves the installed section), and sends the agent's version (`x-scopebond-agent-version`) and report (`x-scopebond-tool-settings`) on the agent's rules check. The Scopebond Agent applies a section only when a trusted key signed it (otherwise `refused: unsigned`, nothing written): to Claude Code's `~/.claude/settings.json` (`permissions.allow`/`deny`, `allowedMcpServers`/`deniedMcpServers`) and the Cursor CLI's `~/.cursor/cli-config.json` (`permissions.allow`/`deny`, denied servers as `Mcp(<name>:*)`); Codex and GitHub Copilot are reported as unsupported. Other keys and entries stay, the file is backed up once and replaced atomically, a file that does not parse is never written, and each tool is reported as applied, drifted (setting names only, never values) or refused; a drift is put back only in enforce mode.
